# --- Custom fields to refresh onto tickets (generic; NO defaults) ---
# Comma-separated: field_id or field_id:column_name. Each configured field is
# re-fetched every poll cycle, overwritten on the ticket, and emitted as a JSON
# column on `issues` (column = the alias, or the field id). A column that would
# collide with a built-in issues column (e.g. `resolution`) is prefixed with `cf_`.
# SLA fields are just entries here — e.g.
#   customfield_10328:first_response,customfield_10161:time_to_resolution
# Discover field ids:   python -m connectors.jira.scripts.verify_sla_access --list-fields
# Verify on a ticket:   python -m connectors.jira.scripts.verify_sla_access --issue SUPPORT-123
# Leave empty to refresh nothing.
JIRA_REFRESH_FIELDS=

# --- Organization detail fields -> columns on `organizations` (generic; NO defaults) ---
# Comma-separated: detail_key or detail_key:column_name, where detail_key is matched
# against a JSM organization detail's `id` first and its `name` second. Prefer the id —
# it survives a rename of the detail field, the label does not. Each configured detail
# becomes a column on the `organizations` table, which maps the ids in
# `issues.organization_ids` to the organization's current name plus these values. That
# lets tickets be joined to whatever the detail points at (a CRM account id, a region,
# an account owner) instead of matching on organization names, which drift. E.g.
#   JIRA_ORG_DETAIL_FIELDS=38:crm_account_id,41:region
# Discover detail ids:  GET /jsm/csm/cloudid/{cloudId}/api/v1/organization/{orgId}
#                       (ids appear ONLY on this per-organization endpoint; the batched
#                        profile/fetch and /organization/details return names only)
# Refreshed daily by the `jira-org-refresh` job. Empty still emits org_id + name.
JIRA_ORG_DETAIL_FIELDS=
