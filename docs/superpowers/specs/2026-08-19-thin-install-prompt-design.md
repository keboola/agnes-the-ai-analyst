# Thin install prompt + `agnes onboard` — design

Date: 2026-08-19
Status: approved (brainstormed interactively; approach 1 of 3 chosen)

## Problem

The Claude Code setup prompt generated by `app/web/setup_instructions.py`
(1357 lines of Python producing a 400–550 line English "program" executed by
the agent) hurts on three axes at once:

- **UX** — the onboarding page is intimidating; users paste a wall of text.
- **Reliability** — a long English program run by a non-deterministic
  interpreter (the agent) skips steps and mis-triages errors.
- **Maintenance** — a large module, byte-identical Python+JS render contract,
  snapshot tests, and inlined connector SKILL.md bodies.

Measured on a live instance (543 rendered lines): base steps ≈ 190 lines,
connector blocks ≈ 275 lines (>50 %), preamble/finale ≈ 55 lines. The TLS
trust block (~120 lines) no longer renders there because the instance moved
to a Let's Encrypt cert and `_read_agnes_ca_pem` auto-detects publicly
trusted chains.

## Decision

Move orchestration from English into the CLI; shrink the prompt to a stub.

### A. User flow (unchanged page structure on /home)

1. Install Claude Code (unchanged).
2. Save the login token to `~/.agnes/token` (unchanged existing step).
3. Copy a **thin prompt** (~20–25 lines) into Claude Code:
   - install the CLI (`uv tool install …` + missing-uv / PATH recovery),
   - run `agnes onboard --workspace .` and follow its output,
   - restart Claude Code, then a short confirm/recap.

### B. `agnes onboard` — CLI orchestrator (new command)

Deterministic state machine composing existing building blocks:

```
0. workspace-dir check   (unsafe / prepared / unrelated — ported from prompt step 2)
1. init                  (auth via ~/.agnes/token or saved credential; workspace, hooks, first pull)
2. catalog smoke         (old step 4)
3. preflight             (git + claude on PATH — old step 5)
4. marketplace           (refresh-marketplace --bootstrap — old step 6)
5. diagnose              (old step 7)
6. summary               (installed vs already-present; available connectors; NEXT: instructions)
```

- Idempotent: on an initialized workspace each step converges (init defers to
  the `agnes update` reconcile semantics).
- Output is designed for both humans and agents: numbered progress lines and
  a final `NEXT:` block. `--json` emits a machine-readable report.
- Interactive decisions (unsafe/unrelated cwd) are returned as explicit
  instructions with distinct exit codes; the agent relays them. The CLI never
  creates or changes directories on its own.

### C. Thin prompt (`setup_instructions.py` rewrite)

- Module shrinks to ~150 lines. Deleted from the prompt: preflight,
  marketplace, diagnose, connector blocks, step-number machinery — all now
  live inside `agnes onboard`.
- **Self-signed scenario stays automatic**: when `_read_agnes_ca_pem` returns
  a PEM, the existing TLS trust block (step 0) is emitted unchanged — it is a
  pre-CLI bootstrap and cannot move into the CLI. Public-cert (Let's Encrypt)
  instances render no extra block. This is the scenario parameterization:
  driven by the served cert, no manual switch.
- The clipboard partial `_claude_setup_instructions.jinja` stays (it is a
  thin loop over the same Python lines, not a real duplicate renderer); only
  the content shrinks. The snapshot test is rewritten for the thin default.
- The admin override in `/admin/prompts` (editor + git source_mode) is
  untouched and still wins over the default.

### D. Connectors — conversational, post-install (variant A)

- Connector bodies disappear from the prompt entirely.
- `agnes connector list` / `agnes connector show <slug>` (new CLI) — reads
  the manifest/bodies from the server (new small authenticated API endpoint
  backed by `src/connectors_manifest.load_manifest` +
  `_load_connector_body`), so both IWT and default-mode workspaces work.
- The `onboard` summary lists available connectors: "run `/connect` in
  Claude Code or just ask (e.g. 'set up Jira')".
- Connector SKILL.md files themselves are unchanged — they already are agent
  playbooks, and IWT-configured instances already distribute them into
  workspaces via the template sync.

### E. Compatibility, tests, docs

- `/setup` page and dashboard CTA render through the same pipeline, just
  shorter. Operators who want the old long prompt can pin it as an admin
  override (versionable via git source_mode).
- Tests: unit tests for the onboard state machine + dir-check matrix; thin
  prompt snapshot; API endpoint tests; existing prompt tests updated.
- Docs: QUICKSTART + ONBOARDING updated to the new flow; DEPLOYMENT gains an
  explicit Let's Encrypt section (`CADDY_TLS="tls <email>"`) noting the
  install prompt drops the TLS block automatically.
- CHANGELOG: Changed (install flow), Added (`agnes onboard`, connector CLI).

## Out of scope (follow-up efforts)

- Named prompt scenario management + preview/test + LLM-assisted editing in
  `/admin/prompts` (separate spec once the thin variant exists).
- Generalizing the Cowork bundle to a zero-prompt flow (`agnes onboard` is
  the piece its SessionStart hook would call; nothing here blocks it).
