How Jira stays fresh

Jira pushes changes to Agnes over a webhook — no polling schedule. After connecting, register the webhook in Jira’s admin (we’ll show the exact URL and secret), and issues, sprints and worklogs update within seconds of changing.

Design note — one flow, many connectors. Step 1 is the only step that varies by source: each connector brings its own connect form (Keboola: URL + tokens; BigQuery: project + the instance service account; CSV: an upload; Jira: site + webhook). Steps 2–4 are identical for all of them, because once tables exist, bundling and sharing don’t care where the data came from. The semantic-layer token stays a Keboola-only affordance — offered here, skippable, resurfacing as a warn chip on the source if skipped. Google Workspace is deliberately absent: it is the identity provider, not a data source — it lives in People (sign-in + group sync), with its credentials in Instance → Secrets.

Design note — the safety net makes skipping safe. Step 4 is a stack of per-package share cards — each one the SAME component as the package detail’s Sharing panel, so there is one thing to learn. It doesn’t have to guarantee sharing: an unshared package warns on its own card and is counted by Overview’s “packages shared with nobody” gap card, so “Skip for now” moves the work to a visible queue instead of hiding it. The bulk action covers the common “one group gets everything” case; the summary is honest about what reached people and what is still waiting.
